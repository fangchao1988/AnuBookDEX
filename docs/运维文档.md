# Anubis 引擎部署（与 Aleo 并存）

双链并行部署：Aleo 引擎（9000）+ Anubis 引擎（9001），前端 Nginx 按路径前缀分流。

## 架构

```
浏览器
  │
  ├─ /              → Aleo 引擎   (engine:9000)
  ├─ /api /order /ws → Aleo 引擎
  └─ /anubis/*      → Anubis 引擎 (engine-anubis:9000, 去前缀转发)
```

前端切到 Anubis 链时，REST/WS 自动改用 `/anubis/` 前缀（见 `web/src/lib/api/anubis.ts` 的 `ANUBIS_BASE` 与 `chain.ts` 的 `wsClient.setPath`）。

## 首次部署（一次性）

1. **准备密钥文件**（服务器上，项目根目录）
   ```bash
   cp .env.anubis.example .env.anubis
   vim .env.anubis
   #   ANUBIS_PRIVATE_KEY_METAMASK=0x...   # operator 结算私钥（需在 Settlement 上被 authorizeEngine）
   #   ANUBIS_VIEW_KEY=0x...               # 隐私解密私钥（可留空，留空则隐私下单不可用）
   chmod 600 .env.anubis
   ```
   > `.env.anubis` 已在 `.gitignore`，不会被提交。

2. **确认配置模板存在**：`conf/test-anubis.yaml`（已随仓库提交，含测试网合约与代币地址）

3. **触发部署**：打 tag 推送（CI 构建 3 个镜像并 SSH 部署）
   ```bash
   git tag v1.0.6 && git push origin master v1.0.6
   ```

## 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| `engine-anubis` 起不来，compose 报 `env file not found` | 缺 `.env.anubis` | 按上面第 1 步创建 |
| 前端 Anubis 链请求 404 | nginx 未更新 | 重新部署 web 镜像（`docker compose up -d --force-recreate web`） |
| 前端 Anubis 链行情不更新 | WS 仍连 Aleo 引擎 | 确认切链后 `wsClient.setPath` 生效（浏览器 Network 看 `/anubis/ws`） |
| 结算一直失败 `Not authorized engine` | operator 地址未授权 | 在 Settlement 合约上 `authorizeEngine(<operator>, true)` |

## 与 Aleo 部署的关系

两套引擎**完全独立**：独立镜像、独立容器、独立数据卷（`engine-anubis-data`/`engine-anubis-logs`）、独立密钥文件。停掉其中一个不影响另一个。
