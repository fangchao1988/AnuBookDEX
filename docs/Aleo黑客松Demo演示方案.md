## 2. 演示流程时间轴

### 0:00–0:40 开场：痛点

> "今天的 DEX 面临一个根本矛盾：**交易越透明，就越容易被 MEV 机器人抢跑**。Uniswap 上有超过一半的交易被夹击（sandwich attack）。中心化交易所解决了流动性，但用户资产由他人托管。我们想证明一件事：**在 Aleo 上，可以同时拥有『中心化交易所的撮合体验』和『链上的资产自托管』，并且交易内容是加密的**。"

### 0:40–1:30 架构一句话（放架构图）

> "我们的架构叫**『链上托管、链下撮合、零知识结算』**：订单以加密 record 托管在 Aleo 链上（operator 也无法读取）；撮合在链下的 Go 引擎完成（红黑树订单簿，价格-时间优先）；成交后通过 **ZK 证明的 settle 交易**在链上完成资产互换——每一步都有密码学保证，不需要信任我们。"

### 1:30–2:00 演示前奏：连接钱包 + 余额展示（ALEO/USDCX 交易页）

> "用 Shield 钱包连接。大家看资产页——我们实现了**公开/隐私余额分离**：ALEO 总余额 = 公开 + 隐私。标准下单用公开余额，隐私下单用链上加密 record。订单簿里已经有两笔卖单，我们先演示**标准下单**。"

### 2:00–3:30 演示①：标准（公开）下单 → 撮合 → 结算

1. 交易页选「标准」tab → 买入 0.016、数量 1（钱包侧确认签名）
2. **讲解词**（等待钱包确认 + 链上确认 ~30-60s）：

> "钱包正在执行两笔链上交易：先把公开 USDCX 托管给 operator，再调用 `place_order_buy_public` 把订单写入合约的 `public_orders` 映射。订单参数**链上公开**——这就是'标准'模式的含义。"

3. 撮合瞬间（订单簿刷新）：
> "买单进入撮合引擎，与 0.016 的卖单**价格-时间优先**匹配。撮合是毫秒级的——Aleo 只是托管和结算层，撮合体验和中心化交易所一致。"

4. 结算（~90s 等待）：
> "结算正在生成零知识证明。引擎先让 operator 把 ALEO 公开转账给买家，再广播 `settle_vp`——合约在 finalize 阶段校验卖单状态、金额，然后**原子互换**：买家收到 ALEO，卖家收到 USDCX，订单标记为已结算。这里的关键：**operator 无法篡改任何一笔成交**，因为合约校验 + 证明生成都在链上。"

### 3:30–4:30 演示②：链上验证

> "看成交面板——settle_status 从 '结算中' 变成 '已结算'。链上验证：`public_orders` 映射里这笔订单的 `status=1`。每一笔成交都可以在 Aleo explorer 上查到完整交易，**没有任何服务器数据库，全是链上事实**。"

### 4:30–6:00 演示③：隐私下单（「隐私」tab）

> "现在切到隐私模式——这是 Aleo 原生隐私的体现。钱包把 **USDCX Token record + 合规凭证**以**加密 record** 托管到链上：订单的价格、数量、方向全部加密，**只有 operator 的 view key 能解密**，对手方、矿工、甚至我们团队都看不到明文。HTTP 请求里只传 tx_id，不传任何订单参数。"

> "结算走 `settle_vp`：**隐私 record 互换 + 零知识证明**，卖家收到加密的 USDCX，买家收到 ALEO。注意这条链路上没有公开价格——**隐私单和公开单在同一订单簿撮合**，这就是'公开/隐私混合'。"

### 6:00–6:40 演示④（可选）：撤单

> "不想成交了？一键撤单：公开订单 operator 直调转账退回公开余额；隐私订单消费 Order record 全额退回——所有资产**原路返回**。"

### 6:40–8:00 收尾 + 技术亮点

> "总结三个关键词：**自托管**（资产永远在你的链上地址）、**可验证**（撮合结果链上可审计）、**混合隐私**（同一订单簿里标准单和隐私单共存）。引擎是 Go 无锁并发，单交易对独立 goroutine；合约支持 4 种下单 × 4 种结算 × 4 种撤单的组合矩阵。感谢评委，欢迎提问。"

## 4. QA 预判（评委高频问题）

1. **为什么链下撮合？**
   性能（Go 无锁订单簿、毫秒撮合）+ 隐私（订单加密，撮合器不可见明文）。Aleo 只做托管/结算，链上验证撮合结果。

2. **撮合结果可信吗？**
   订单在链上加密托管，成交有 ZK 证明 + 合约 finalize 校验（side/status/金额断言），operator 无法伪造成交。

3. **和中心化交易所的区别？**
   资产自托管（record 归用户），撮合可审计，operator 跑路资产仍在链上。

4. **隐私和合规怎么平衡？**
   合规凭证 + 冻结列表：`transfer_private_with_creds` 用 ZK 证明验证凭证在合规列表内，**证明合规而不泄露身份**。

5. **性能瓶颈？**
   撮合毫秒级；瓶颈在 Aleo 证明生成（60-90s/笔），可用并行证明、批量结算优化。

6. **和暗池/MPC 的关系？**
   隐私单已是链上加密；暗池（MPC 撮合）是路线图——多签名 MPC 让撮合者也不可见。

7. **凭证轮换是什么？**
   operator 凭证是 UTXO，每笔结算消费后自动轮换——系统已实现在链上跑通（多笔成交自动续凭证）。

## 5. 技术要点备忘（答辩引用）

- **撮合核心**：Go 红黑树订单簿（价格-时间优先），每交易对独立 goroutine、channel 驱动、无锁
- **隐私下单**：`place_order_buy/sell_private`，Order record 加密托管 + view key 解密
- **结算矩阵**：4 下单 × 4 settle（pp/vp/pv/vv）× 4 撤单
- **链上校验**：`public_orders.status==1`（settled）/ `==2`（cancelled），不轻信广播返回（already-exists 幂等误判教训）
- **凭证生命周期**：operator 凭证 UTXO 单次消费 → 结算后自动捕获新凭证轮换 + 状态文件持久化
- **实测数据**：ALEO/USDCX 多笔真实 testnet 成交，`status=1` 链上确认，凭证自动轮换 N 次
